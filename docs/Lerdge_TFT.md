# Сенсорный экран Lerdge (TFT по FSMC) в Klipper

Этот форк добавляет в Klipper поддержку штатных сенсорных экранов плат
Lerdge (проверялось на разборе прошивки Lerdge-K V4.3.3). Экран работает
как полноценный дисплей Klipper: статус печати, всё стандартное меню
(`[menu ...]`), печать с SD (`virtual_sdcard`), прогрев, перемещение осей
и т. д. Управление — пальцем.

## Как это устроено

Экран Lerdge — «тупой» TFT-модуль без своего процессора: контроллер
ST7796S (480×320) висит прямо на параллельной 16-битной шине FSMC
микроконтроллера STM32F407, тач (резистивный, XPT2046) — на SPI3.
Поэтому поддержка состоит из двух частей:

* **Прошивка MCU** (`src/stm32/tft_fsmc.c`) — настраивает FSMC и
  выполняет простые команды рисования: команда контроллера, заливка
  прямоугольника, монохромный битмап с масштабом и цветами. Команды
  разрешены и после аварийной остановки (shutdown), чтобы на экране было
  видно ошибку.
* **Хост** (`klippy/extras/display/lerdge_tft.py`) — инициализирует
  контроллер, рисует экран Klipper 16×6 символов (шрифт 8×16 ×3 =
  384×288 пикселей) и столбец сенсорных кнопок ▲ ▼ ✓ ◄, опрашивает тач
  через обычный SPI, переводит касания в события меню.

### Что извлечено из заводской прошивки Lerdge-K V4.3.3

Файл `Lerdge_K_firmware_*.bin` зашифрован побайтовой подстановкой
(тот же алгоритм, что в `scripts/update_lerdge.py`). После расшифровки
и дизассемблирования (приложение слинковано на `0x08010000`) найдены:

| Что | Значение |
| --- | --- |
| Контроллер | ST7796S, 480×320, RGB565, инверсия включена |
| Шина | FSMC банк 1 (NE1 = PD7), 16 бит, RS = A16 (PD11) |
| Регистр команд / данных | `0x60000000` / `0x60020000` |
| Тайминги записи | ADDSET = 4, DATAST = 10 (HCLK 168 МГц) |
| RESET / подсветка | PD6 / PD3 |
| Тач | XPT2046 на SPI3 (PB3 SCK, PB4 MISO, PB5 MOSI), CS = PG15, PENIRQ = PG12 |
| Чтение тача | команды 0x90/0xD0, 12 замеров, сортировка, среднее по 8 |

Init-последовательность ST7796S из прошивки перенесена в
`ST7796S_INIT` без изменений. Дополнительно есть ILI9488 и ILI9341 (на
случай других экранов/ревизий): контроллер определяется автоматически
чтением ID (команда `0xD3`).

## Сборка прошивки MCU

```
cd ~/klipper
make menuconfig
```

* Micro-controller Architecture: **STMicroelectronics STM32**
* Processor model: **STM32F407**
* Bootloader offset: **64KiB bootloader**
* Clock Reference: **8 MHz crystal**
* Communication interface: как у вас сейчас (USB на PA11/PA12 или UART)

Опция «Support parallel (FSMC) TFT displays» для STM32F4 включена по
умолчанию. Затем:

```
make
python3 scripts/update_lerdge.py out/klipper.bin /путь/к/корню/TF-карты
```

Скрипт создаст `Lerdge_K_system/Firmware/Lerdge_K_firmware_force.bin`.
Вставьте карту в плату и включите питание — загрузчик Lerdge прошьёт
файл. После прошивки **удалите папку `Lerdge_K_system` с карты**, иначе
прошивка будет записываться при каждом включении.

## Настройка printer.cfg

Минимальный вариант для Lerdge-K (полный список опций —
`config/sample-lerdge-tft.cfg`):

```
[display]
lcd_type: lerdge_tft
reset_pin: PD6
backlight_pin: PD3
touch_cs_pin: PG15
touch_spi_bus: spi3
touch_int_pin: ^!PG12
```

При первом запуске (пока в конфиге нет `touch_calibration`) экран
сразу покажет калибровку: по очереди коснитесь центров пяти крестиков.
Затем выполните `SAVE_CONFIG`. Перекалибровать можно командой
`TOUCH_CALIBRATE`.

## Управление

* Касание статус-экрана — открыть меню.
* ▲ / ▼ — перемещение по меню (удержание — автоповтор, затем ускорение);
  при редактировании значения — увеличить / уменьшить.
* ✓ — выбрать (долгое нажатие — `long_click`).
* ◄ — назад.
* Касание строки меню выделяет её, повторное касание — выбирает
  (`touch_tap_activates: True` — выбор с первого касания).

## G-code команды

* `TOUCH_CALIBRATE` — калибровка тача.
* `TFT_REDRAW` — перерисовать экран; `TFT_REDRAW INIT=1` — заново
  инициализировать контроллер (если экран «завис» или побелел).

## KlipperScreen на экране Lerdge (режим зеркала)

Вместо встроенного меню на экран можно вывести полноценный KlipperScreen.
Он работает на виртуальном X-дисплее (Xvfb, 480×320), а
`scripts/lerdge_mirror.py` читает кадры из буфера Xvfb, находит
изменившиеся области, сжимает их (RLE) и передаёт модулю `lerdge_tft`
через API-сокет Klipper (`lerdge_tft/draw`). Касания тача приходят обратно
(`lerdge_tft/subscribe_touch`) и превращаются в клики мыши в X.

Если зеркало не присылает данные дольше 20 секунд, экран сам возвращается
к встроенному меню.

Нужно:

* пакеты `xvfb python3-numpy python3-xlib`;
* второй экземпляр KlipperScreen с отдельным конфигом
  (`-c ~/printer_data/config/KlipperScreen-lerdge.conf`) и `DISPLAY=:99`;
* `Xvfb :99 -screen 0 480x320x24 -fbdir /dev/shm/lerdge`;
* `python3 ~/klipper/scripts/lerdge_mirror.py` (по умолчанию `:99` и
  `/dev/shm/lerdge/Xvfb_screen0`).

Полный кадр KlipperScreen после сжатия занимает около 30 КБ. На 250000
бод это ~1,4 с, поэтому скорость UART лучше поднять. Для Orange Pi и
STM32F407 без погрешности подходит 1500000: собирайте прошивку с
`CONFIG_SERIAL_BAUD=1500000` и `CONFIG_SERIAL_BAUD_FALLBACK=250000`.
Пока не придёт первая корректная команда, MCU каждые 20 секунд
переключается между этими скоростями, так что хост сможет подключиться
на 250000, если провода не тянут высокую скорость.

## Обновление прошивки удалённо

TF-карта (FAT32) остаётся в плате. Klipper нужно остановить:

```
sudo systemctl stop klipper
./scripts/flash-sdcard.sh -b 1500000 /dev/ttyS3 lerdge-k
```

Прошивка записывается на карту через работающую прошивку (программный
SPI). Загрузчик Lerdge читает карту в режиме SDIO, а карта, к которой
обращались по SPI, возвращается в режим SDIO только после снятия питания.
Поэтому после записи выключите хост, выключите и включите принтер, а затем
выполните проверку – она сверит версию и удалит файл с карты (иначе
загрузчик ставит прошивку при каждом включении):

```
sudo systemctl stop klipper
./scripts/flash-sdcard.sh -c -b 1500000 /dev/ttyS3 lerdge-k
sudo systemctl start klipper
```

## Возможные проблемы

* **Белый экран** — контроллер не инициализировался. Проверьте, что MCU
  прошит этой сборкой (в `klippy.log` должна быть строка
  `lerdge_tft: display id ...`). Если ID читается как `0000`/`ffff`,
  задайте `controller: st7796` явно.
* **Перепутаны цвета / негатив** — `invert_colors: True` или `False`.
* **Изображение вверх ногами** — `rotate_180: True` (калибровка тача
  при этом сохраняется).
* **Касания не срабатывают** — уменьшите `touch_pressure_threshold`
  (по умолчанию 300) и проверьте `touch_int_pin`. Без `touch_int_pin`
  тач опрашивается постоянно (10 раз в секунду).
* **Артефакты на картинке** — увеличьте `fsmc_write_datast` (например,
  до 15) и `fsmc_write_addset` (до 8).
